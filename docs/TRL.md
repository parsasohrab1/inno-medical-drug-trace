# شواهد بلوغ فناوری (TRL) — inno-medical-drug-trace

**ادعا: TRL 4** (اعتبارسنجی اجزا در محیط آزمایشگاهی). **TRL 5 ادعا نمی‌شود.**

## شواهد
| سطح | شاهد |
|---|---|
| TRL 2 | مفهوم و معیار موفقیت در README و جدول زیر تعریف شده است. |
| TRL 3 | اثبات مفهوم روی داده‌ی مصنوعی: `src/inno_medical_drug_trace/core.py`، تولیدکننده‌ی داده‌ی قطعی (`generate`). |
| TRL 4 | اجزا (داده → مدل/قواعد → هشدار/خروجی) با تست واحد و معیارهای پذیرش خودکار روی ۳ seed مستقل؛ CI در `.github/workflows/ci.yml`. |

## معیارهای پذیرش TRL 4
| معیار | شرط |
|---|---|
| forecast WAPE improvement over 4-week moving average | >= 0.1 |
| recall of batches that would expire unsold | >= 0.8 |
| precision of expiry alerts | >= 0.7 |
| recall of true 4-week shortages | >= 0.8 |
| precision of shortage alerts | >= 0.7 |

نتایج اجرا: [VALIDATION.md](VALIDATION.md) (بازتولید: `python -m inno_medical_drug_trace validate`).

## آنچه پیاده‌سازی شده
`core.forecast` (رگرسیون هارمونیک هفتگی + اصلاح سطح اخیر)، هشدار انقضا/کمبود با مصرف FIFO، `suggest_transfers` (انتقال حریصانه، بدون عبور از مازاد مبدأ).

## فرض‌های داده‌ی مصنوعی و محدودیت‌ها
۸ قلم دارو × ۴ مرکز × ۱۵۶ هفته؛ مصرف پواسون با فصلی‌بودن سالانه و روند؛ دسته‌های دارویی با انقضای ۱ تا ۴ هفته؛ شوک عرضه/تحریم در داده نیست.

عملکرد روی داده‌ی مصنوعی تضمین‌کننده‌ی عملکرد روی داده‌ی واقعی نیست. خروجی‌ها پشتیبان تصمیم‌اند و جایگزین قضاوت بالینی/کارشناسی نیستند.

## لازمه‌های رسیدن به TRL 5
داده‌ی واقعی و بی‌نام‌شده‌ی موجودی/مصرف چند داروخانه، اتصال به سامانه‌ی رهگیری رسمی، آزمون پایلوت در بیمارستان.
